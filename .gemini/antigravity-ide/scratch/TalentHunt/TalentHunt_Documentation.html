01 Title of the Project

Formal Project Title: Online Talent Hunt and Competition Evaluation System with Java, Servlets, JSP, and Web Technologies

Common Project Name: TalentHunt Management System (or TalentHunt Platform)

System Classification: Interactive Enterprise Web Application for Creative Talent Discovery, Multi-Category Competition Management, Audience Voting, and Structured Judge Evaluation.

Project Summary
TalentHunt is a modern, full-stack Java EE web application engineered to bridge the disconnect between aspiring creative artists and global audiences. The application establishes a transparent, multi-tiered digital ecosystem where contestants register and submit portfolio performances, audience members cast audited votes, certified judges assess submissions across objective scoring rubrics, and administrators oversee competitions and system moderation.

02 Introduction

2.1 Background and Context

Talent discovery has historically been constrained by geographic barriers, paper-bound audition workflows, and subjective evaluation methodologies. Traditional talent scouting requires physical presence, manual registration queues, fragmented score sheets, and non-transparent judging criteria that frequently lead to calculation errors and delayed outcomes.

With the ubiquity of high-speed digital infrastructure and rich web technologies, creative disciplines—such as vocal performance, choreography, instrumental music, graphic arts, stand-up comedy, and technology innovation—demand an open, accessible, and automated medium. The TalentHunt System provides an end-to-end digital lifecycle that manages participant onboarding, media submissions, multi-criteria judge grading, audience engagement, and real-time leaderboard aggregation.

2.2 Problem Statement

Conventional talent competitions and legacy institutional competition systems suffer from multiple critical limitations:

  • Manual and Error-Prone Onboarding: Physical registration and ad-hoc email collection result in duplicate entries, inaccurate contestant credentials, and absence of standardized data validation.
  • Opaque and Inconsistent Scoring: Subjective, non-standardized judging sheets without audit logs risk bias and prevent contestants from receiving transparent, multi-dimensional feedback.
  • Inadequate Access Controls: Systems frequently fail to enforce strict Role-Based Access Control (RBAC), leaving administrative queues vulnerable to unauthorized manipulation.
  • Disjointed User Interaction: Traditional academic systems lack dynamic, responsive client-side interfaces, forcing full-page reloads and poor mobile usability.

2.3 Significance of the Solution

The TalentHunt platform addresses these bottlenecks by implementing a robust Java EE Model-View-Controller (MVC) architecture. It marries rigorous server-side business rules, session authentication, and database integrity with an engaging, dark-gold glassmorphism user interface. The platform ensures complete auditability of contestant entries, eliminates duplicate audience voting through unique database constraints, and provides dynamic dashboards tailored to contestants and administrators.

04 Scope of the Project

4.1 Functional Scope by User Roles

ROLE Contestant (Participant)

Self-registration with validation; multi-portal login; browse active and upcoming competitions; submit entries with title, category, media URLs, and descriptions; view personal submission history; track real-time leaderboard standing.

ROLE Administrator

Secure administrative authentication; system telemetry overview (user count, submission count, votes, competitions); review pending submissions with approval/rejection capability; manage competition lifecycle.

ROLE Judge

Evaluate approved contestant submissions; score entries on standardized metrics (Technical Execution, Creativity, Presentation on a 1-10 scale); submit qualitative feedback; trigger dynamic average score computation.

ROLE Audience (Voter)

Explore curated talent showcase filtered by category; view multimedia performances; cast verified votes with enforced single-vote per submission constraint; inspect live rank standings.

4.2 Technical and Architectural Scope

  • Separation of Concerns: Presentation (HTML5/JSP), Controller (Java Servlets), Business Logic (Service Interfaces & Implementations), and Persistence (JDBC DAO).
  • Cross-Platform Portability: Dual execution mode supporting deployment as a standard Java EE Web Archive (WAR) on Apache Tomcat 9/10, as well as a zero-dependency standalone Java HTTP server runner.
  • Hybrid Storage Capability: Pre-configured database integration supporting both enterprise MySQL 8.0 Server and an embedded in-memory/file-based H2 Database running in MySQL compatibility mode.

4.3 Boundary Conditions & Limitations (Current Phase)

  • Direct binary video streaming relies on hosted media URLs (e.g., YouTube, Vimeo, cloud CDN links) rather than multi-gigabyte raw video uploads directly to local disk.
  • Payment gateway integration for competition registration fees is earmarked for future releases.

06 Workflow of the Project

The workflow of the TalentHunt platform is organized into a seamless, multi-stage pipeline connecting contestants, audience voters, judges, and administrators. The following flowchart diagram illustrates the procedural lifecycle:

1
Contestant Onboarding & Registration (Phase 1 & 2)

User navigates to registration portal → inputs full name, email, password, and role → client-side JS validates input syntax → server-side ValidationUtil checks string constraints → UserServiceImpl verifies email uniqueness → TalentDao persists record in users table.

2
Authentication & Session Establishment (Phase 4)

Contestant or Admin submits login credentials → LoginServlet validates against database → successful verification creates HttpSession with user attributes (ID, Role, Name) and 30-minute inactivity timeout → dispatches to role-appropriate dashboard.

3
Competition Discovery & Talent Submission (Phase 3 & 4)

Contestant browses active competitions (e.g., Vocal Masters, Choreography Clash) → opens submission modal → enters title, category, media URL (video/audio/image), and description → DAO stores record in talent_submissions with status APPROVED / PENDING.

4
Public Showcase & Audience Voting (Phase 3 & 4)

Audience members view entries on curated showcase cards → clicks "Vote" on an entry → backend queries votes table to verify voter uniqueness → inserts vote record and atomically increments votes_count on the submission.

5
Judge Evaluation & Multi-Metric Scoring

Certified judge accesses submission → scores Technical Execution (1-10), Creativity (1-10), and Presentation (1-10) with written remarks → system computes total & average scores and updates submission ranking.

6
Live Leaderboard Generation & Admin Monitoring

Weighted ranking algorithm sorts entries by average judge scores and audience vote counts → dynamic leaderboard displays Top 3 podium winners → Administrators monitor telemetry in admin-dashboard.jsp → Contestant logs out via LogoutServlet, invalidating session.

07 Modules of the Project (Phase-Wise Explanation)

The system architecture is structured into distinct, modular subsystems designed according to the prescribed course phases and learning outcomes:

Phase 1: Core Application Setup and Design (CLO1)

Goal: Define the core domain entities, model attributes, and establish foundational Java string handling validation.

  • User Entity Identification (com.talenthunt.model.User): Encapsulates primary attributes: id (int), name (String), email (String), password (String), role (String enum: CONTESTANT, JUDGE, AUDIENCE, ADMIN), avatarUrl, bio, and createdAt (Timestamp).
  • Class Structure & Encapsulation: Features default constructors, parameterized constructors, convenience constructors for registration, complete getter and setter methods, and business helper checks (isAdmin(), isContestant(), isJudge()).
  • Basic Validation Logic in Java (ValidationUtil): Utilizes Java String handling and compiled regular expressions to enforce:
    • isNullOrEmpty(String str): Null checks and whitespace trimming.
    • isValidEmail(String email): RFC-5322 compatible regex pattern verification.
    • isValidPassword(String password): Minimum 6-character length enforcement.
    • isValidName(String name): Name length (2-60 chars) and alphanumeric sanitization.
    • sanitize(String input): HTML/script injection character substitution (preventing XSS).

Phase 2: Structured Programming and Reliability (CLO2)

Goal: Establish robust package segregation, interface contracts, and custom exception handling.

  • Package Organization:
    • com.talenthunt.model: Domain entity classes (User, Competition, TalentSubmission, Evaluation, Vote).
    • com.talenthunt.service: Business contract interface (UserOperations).
    • com.talenthunt.service.impl: Business service implementation (UserServiceImpl).
    • com.talenthunt.dao: Data Access Object handling raw JDBC queries (TalentDao).
    • com.talenthunt.db: Database connection pool and schema initialization (DatabaseManager).
    • com.talenthunt.exception: Custom domain exceptions (ValidationException, AuthenticationException, UserAlreadyExistsException).
    • com.talenthunt.util: Validation and JSON parsing helpers (ValidationUtil, JsonUtil).
    • com.talenthunt.servlet: Java EE Servlets and Filters (LoginServlet, RegisterServlet, LogoutServlet, DashboardServlet, AuthenticationFilter).
  • User Operations Contract (UserOperations): Interface exposing methods: authenticate(), register(), validateUser(), isEmailAvailable(), getUserById(), getUserByEmail(), and getAllUsers().
  • Custom Exception Hierarchy: Dedicated runtime/checked exceptions with field-specific diagnostics that decouple presentation from business rule failures.

Phase 3: Web Interface and Client Interaction (CLO2)

Goal: Develop interactive client-side forms, real-time JavaScript validation, and JSON data exchange.

  • Modern Responsive Web Forms: Sleek glassmorphism login, registration, and competition submission dialogs equipped with role tabs (Contestant vs. Admin), visual feedback states, and progress spinners.
  • Client-Side JavaScript Validation: Instant input verification prior to network dispatch using regular expressions, highlighting invalid fields with red borders and floating warning banners.
  • JSON Data Representation: Client-server communication utilizes lightweight JSON payloads. A sample representation (user-sample.json) structures user state and system metrics for asynchronous consumption.

Phase 4: Server-Side Integration and Execution (CLO1, CLO2, CLO3)

Goal: Implement HTTP Servlets, session management, dynamic JSP views, and access control filters.

  • Servlet Integration: LoginServlet and RegisterServlet handle HTTP GET and POST verbs, supporting both standard form submissions and asynchronous AJAX fetch calls.
  • Session Tracking via HttpSession: request.getSession(true) binds the authenticated User instance, user ID, username, and role, governed by a 30-minute inactivity timeout.
  • Dynamic JSP Dashboards: dashboard.jsp renders contestant profile data, submission stats, and open competitions; admin-dashboard.jsp displays system-wide moderation queues and telemetry.
  • Access Control Filter: AuthenticationFilter intercepts requests to protected URLs (/dashboard.jsp, /admin-dashboard.jsp, /admin/*) and redirects unauthenticated users to login.jsp?error=unauthorized.
  • Logout & Invalidation: LogoutServlet executes session.invalidate(), destroying session tokens and preventing back-button access.

8.1 Domain Model: User.java

Java Source Code
package com.talenthunt.model;

import com.talenthunt.exception.ValidationException;
import com.talenthunt.util.ValidationUtil;
import java.io.Serializable;
import java.sql.Timestamp;

public class User implements Serializable {
    private static final long serialVersionUID = 1L;

    public int id;
    public String name;
    public String email;
    public String password;
    public String role; // CONTESTANT, JUDGE, AUDIENCE, ADMIN
    public String avatarUrl;
    public String bio;
    public Timestamp createdAt;

    public User() { this.role = "CONTESTANT"; }

    public User(int id, String name, String email, String password, String role, String avatarUrl, String bio) {
        this.id = id;
        this.name = name;
        this.email = email;
        this.password = password;
        this.role = role != null ? role.toUpperCase() : "CONTESTANT";
        this.avatarUrl = avatarUrl;
        this.bio = bio;
    }

    public void validate() throws ValidationException {
        ValidationUtil.validateRegistration(this.name, this.email, this.password);
    }

    public boolean isAdmin() { return "ADMIN".equalsIgnoreCase(this.role); }
    public boolean isContestant() { return "CONTESTANT".equalsIgnoreCase(this.role); }

    // Standard Getters and Setters ...
    public int getId() { return id; }
    public String getName() { return name; }
    public String getEmail() { return email; }
    public String getRole() { return role; }
}

8.3 Validation Utility: ValidationUtil.java

Java Source Code
package com.talenthunt.util;

import com.talenthunt.exception.ValidationException;
import java.util.regex.Pattern;

public class ValidationUtil {
    private static final Pattern EMAIL_PATTERN = Pattern.compile("^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,6}$");
    private static final Pattern NAME_PATTERN = Pattern.compile("^[A-Za-z0-9 ._\\-()]{2,60}$");

    public static boolean isNullOrEmpty(String str) { return str == null || str.trim().isEmpty(); }
    public static boolean isValidEmail(String email) { return !isNullOrEmpty(email) && EMAIL_PATTERN.matcher(email.trim()).matches(); }
    public static boolean isValidPassword(String password) { return password != null && password.trim().length() >= 6; }
    public static boolean isValidName(String name) { return !isNullOrEmpty(name) && NAME_PATTERN.matcher(name.trim()).matches(); }

    public static void validateRegistration(String name, String email, String password) throws ValidationException {
        if (isNullOrEmpty(name)) throw new ValidationException("name", "Full Name is required.");
        if (!isValidName(name)) throw new ValidationException("name", "Name must be 2-60 valid characters.");
        if (!isValidEmail(email)) throw new ValidationException("email", "Invalid email format.");
        if (!isValidPassword(password)) throw new ValidationException("password", "Password must be >= 6 chars.");
    }

    public static void validateLogin(String emailOrUser, String password) throws ValidationException {
        if (isNullOrEmpty(emailOrUser)) throw new ValidationException("email", "Email or username is required.");
        if (isNullOrEmpty(password)) throw new ValidationException("password", "Password is required.");
    }
}

8.4 Authentication Controller: LoginServlet.java

Java Servlet
package com.talenthunt.servlet;

import com.talenthunt.exception.*;
import com.talenthunt.model.User;
import com.talenthunt.service.UserOperations;
import com.talenthunt.service.impl.UserServiceImpl;
import javax.servlet.ServletException;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.*;
import java.io.IOException;

@WebServlet(name = "LoginServlet", urlPatterns = {"/login", "/api/servlet/login"})
public class LoginServlet extends HttpServlet {
    private UserOperations userService;

    @Override
    public void init() { this.userService = new UserServiceImpl(); }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException {
        String email = request.getParameter("email");
        String password = request.getParameter("password");
        String portal = request.getParameter("portal");

        try {
            User user = userService.authenticate(email, password, portal);
            
            // Session Tracking via HttpSession (Phase 4)
            HttpSession session = request.getSession(true);
            session.setAttribute("user", user);
            session.setAttribute("userId", user.getId());
            session.setAttribute("userRole", user.getRole());
            session.setMaxInactiveInterval(30 * 60); // 30 mins timeout

            if (user.isAdmin()) {
                response.sendRedirect(request.getContextPath() + "/admin-dashboard.jsp");
            } else {
                response.sendRedirect(request.getContextPath() + "/dashboard.jsp");
            }
        } catch (ValidationException | AuthenticationException ex) {
            request.setAttribute("errorMessage", ex.getMessage());
            request.getRequestDispatcher("/login.jsp").forward(request, response);
        }
    }
}

8.5 Security Access Filter: AuthenticationFilter.java

Java Filter
package com.talenthunt.servlet;

import com.talenthunt.model.User;
import javax.servlet.*;
import javax.servlet.annotation.WebFilter;
import javax.servlet.http.*;
import java.io.IOException;

@WebFilter(filterName = "AuthenticationFilter", urlPatterns = {"/dashboard.jsp", "/admin-dashboard.jsp", "/admin/*"})
public class AuthenticationFilter implements Filter {
    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        HttpServletRequest request = (HttpServletRequest) req;
        HttpServletResponse response = (HttpServletResponse) res;

        HttpSession session = request.getSession(false);
        boolean loggedIn = (session != null && session.getAttribute("user") != null);

        if (!loggedIn) {
            response.sendRedirect(request.getContextPath() + "/login.jsp?error=unauthorized");
            return;
        }

        User user = (User) session.getAttribute("user");
        String uri = request.getRequestURI();

        if (uri.contains("admin") && !user.isAdmin()) {
            response.sendRedirect(request.getContextPath() + "/dashboard.jsp?error=forbidden");
            return;
        }

        chain.doFilter(req, res);
    }
}

09 Features of the Project

1. Dual-Portal Authentication

Seamlessly segmented login portals for contestants and platform administrators, ensuring role separation and privilege verification before dashboard access.

2. Multi-Tier Input Validation

Synchronized client-side JavaScript regex checking and server-side Java string validation (ValidationUtil) preventing SQL injection, malformed emails, and invalid input strings.

3. Robust Session Management

Enterprise HttpSession state tracking with 30-minute inactivity timeouts, HTTP-only cookie configuration, and full session destruction on logout.

4. Automated Ranking & Live Leaderboard

Real-time calculation aggregating verified audience votes and multi-metric judge scores to dynamically highlight top contestants on an interactive podium.

5. Audited Audience Voting

Audience voting secured by unique database constraints (submission_id + user_id), preventing double voting and ensuring fair competition integrity.

6. Standardized Judge Evaluation

Objective rubric-based scoring across Technical Execution, Creativity, and Presentation (1-10 scale) paired with qualitative written judge feedback.

7. Dark-Gold Glassmorphism UI

Aesthetically crafted user interface utilizing dark cosmic gradients, gold metallic accents, smooth micro-animations, and responsive layout grids.

8. Dual Execution Modes

Engineered for zero-configuration testing via an embedded HTTP server runner (run.bat) as well as production WAR deployment on Apache Tomcat.
